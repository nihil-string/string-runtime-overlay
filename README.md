# String 职能与本次设置悬浮窗

## 用法

安装并启用 StringDownloader 后，OverlayPlugin 会在下次初始化时自动创建 `String 职能分配`，不需要手动新建悬浮窗。已有同名或相同地址的窗口会直接复用。

若只单独使用静态页面，也可以手动新建“数据统计”悬浮窗并填写：

   ```text
   https://nihil-string.github.io/string-runtime-overlay/
   ```

平时悬浮窗只显示 8 人职能列表和底部两个轻量操作入口，不再因鼠标移入自动展开。首次遇到队员时会按职业优先级自动分配；之后可拖拽玩家换位，或聚焦玩家名后用方向键调整，手动结果会跨队伍按玩家记忆。左下按钮恢复以下职业默认顺序，右下按钮打开“本次设置”。职能变更后会自动广播，不需要手动广播；战斗中也可拖拽、使用方向键或恢复默认，新职能用于后续尚未结算的机制。

- `MT → ST`：战士、暗黑骑士、绝枪战士、骑士。
- `H1 → H2`：白魔法师、占星术士、贤者、学者。
- `D1 → D2` 近战：武士、武僧、钐镰客、龙骑士、蝰蛇剑士、忍者。
- `D3` 远程物理：机工士、吟游诗人、舞者。
- `D4` 法系：绘灵法师、召唤师、赤魔法师、黑魔法师。队内有至少两个法系且包含黑魔法师时，黑魔法师默认进入 `D2`；其他法系继续按上述顺序竞争 `D4`。

## 绝妖星本次设置

- 点击右下设置按钮时会切换为独立设置界面并自动扩大 OverlayPlugin 窗口；设置界面不显示职能名单，点击“返回”后才恢复为紧凑职能列表。
- 设置方案中的选项统一使用页面内自绘菜单；这是为了绕过 OverlayPlugin 离屏渲染不支持原生 `<select>` popup 的限制。打开菜单时窗口会随内容扩大，选定或点击其他位置后再恢复正常尺寸。
- 设置页只使用唯一的“默认配置”，不提供档案切换、另存或管理入口。无桥接的普通页面也可以修改和保存，但普通浏览器与 ACT 悬浮窗不共享存储。
- 未进入绝妖星时修改会直接保存；进入绝妖星（Zone 1363）后自动载入默认配置，战斗内外的修改都会自动保存并热应用，不再要求额外点击“应用本次”。
- P1-P5 使用左侧阶段栏切换，只展示当前阶段的设置。
- 当前阶段的内容固定按“标点功能”“播报与提示”“绘图与引导”排列；阶段策略也归入其实际影响的功能分类，不再显示没有实际控制项的汇总行。
- 所有完整职能顺序默认只显示 `T / D / N` 三个可拖动分组；点击某个分组后才显示 `MT/ST`、`D1-D4` 或 `H1/H2` 的组内顺序。P3 一二三目标优先级默认共用一条总顺序，点击“细分”后才分别调整三个目标。
- P5 可以分别设置连续地火预显数量、地火两步法个人路线、是否启用遗弃末世个人引导，以及从第几轮开始引导；关闭地火个人路线不隐藏危险圆，个人引导仍同时受原生绘图总开关、P5 阶段开关和个人引导总开关约束。
- “保存设置”在未进本或无桥接时也可用；无桥接只保存到当前浏览器，不会伪装成已下发到 ACT。
- 自动标点、阶段标点、原生绘图和个人引导默认关闭；播报类按现有安全默认启用，但 P2 八轮塔文字提示仍默认关闭。
- 小队消息只有“发送 `/p`”或“不发送”两种状态，默认不发送；不提供个人 `/e` 或个人 TTS。
- 战斗中方案、优先级和职能保持可编辑。修改用于后续尚未结算的机制；P1 光线、P3 火 Buff、P5 交响曲等已经在机制开始时锁存的顺序不重算，P3 一二三目标会在实际出标前读取最新优先级，但标记一旦发出便不因后续修改而重排。关闭自动标点、阶段标点、原生绘图或小队消息仍会立即阻止后续输出并执行各自清理。
- 无桥接时配置只保存在当前页面所属的浏览器。只有带 OverlayPlugin/StringDownloader 桥接的 ACT 悬浮窗会把设置写入 ACT；如果同一个 ACT 悬浮窗只是暂时断线，桥接恢复后会继续同步。桥接不可用或职能悬浮窗未持续提供有效 8 人职能表时，不发送新的自动标点或小队消息。

## 连接状态

- `已连接`：已经连到 OverlayPlugin，进入小队/副本后会自动读取 8 人列表。
- `连接中` / `离线`：没有拿到 OverlayPlugin API，此时只显示 `MT/ST/H1/H2/D1-D4` 职能占位，不会显示演示姓名，也不会广播。

触发器只在最近 4 秒内收到与当前 8 人小队完全一致的职能表时授权新的自动标点和 `/p`。悬浮窗关闭、离线、职能重复或成员变化都会撤销授权。

如果在 ACT 里一直是 `离线`，优先用 OverlayPlugin 的 URL Generator/WS Server 方式创建悬浮窗，确保 URL 带有 `OVERLAY_WS` 参数，或使用会注入 OverlayPlugin API 的悬浮窗类型。

## 发布范围

这个仓库只发布职能分配悬浮窗的静态文件，不包含 cactbot 触发器、ACT 日志或私有配置。

## 协议

悬浮窗通过 OverlayPlugin broadcast 发送：

```js
{
  source: 'stringRuntimeJS',
  msg: {
    party: [
      { id: 'actor id', name: 'player name', rp: 'MT' },
    ],
  },
}
```

`[必装] 依赖 - String运行库.js` 会监听 `stringRuntimeJS`，并提供 `data.stringFL.getRpByName(data, name)` 给触发器使用。
